# DSHChatMode · 主动聊天

> Let your DeepSeek Harness assistant start the conversation for once. On your schedule, in your persona, inside the chat you choose.

A DeepSeek Harness (DSH) plugin that makes the model **proactively message you**: on a rhythm you set, during the hours you allow, about the things you care about — and then simply keep chatting when you answer.

![DSHChatMode icon](icon.svg)

## What it does

- **Timed pings, not a chat bot.** During active hours it fires every 10 / 20 / 30 / 60 minutes (or any custom interval), with optional random jitter so it never feels like a metronome.
- **Quiet when you are.** Work hours are configurable, and DND windows (e.g. lunch and 23:00–08:00) always win. Daily caps and a "don't interrupt a running turn" check keep it human.
- **Your persona, not a canned script.** Pings are generated by the model in the target conversation, so whatever persona / memory plugins you use (soul, memories, AGENTS.md…) apply automatically. It reads the recent history before speaking and won't repeat openers.
- **You choose where it lands.** A dedicated, retained conversation (created on first delivery) or any existing conversation you bind it to.
- **Topics you actually want.** Default pool: care, gossip, health & sleep, weather, work progress, a lone emoji, "I miss you / I'm bored" — plus a free-form "extra flavor" box.
- **Two ways to drive it.** A real settings page in **Settings → 主动聊天**, or just ask the assistant in chat ("message me every 30 minutes", "don't disturb me at lunch").

## Install

Requires **DSH ≥ 0.2.2-rc.1** and **Node ≥ 22.12**.

```bash
dsh plugin --profile desktop add dsh-chatmode-plugin
```

Or open **Plugins → Add plugin** in DSH and enter `dsh-chatmode-plugin`, then restart DSH.

A market submission for the [Open Plugin Market](https://dshopen.org) is prepared; once accepted you can also add that index source in **Discover** and install from the market page.

After restart you will find **Settings → 主动聊天** in the desktop client.

## Quick start

1. Open **Settings → 主动聊天** (the page sits after 「灵魂」 in the sidebar).
2. Turn on **打开主动聊天**, pick an interval (10 / 20 / 30 / 60 minutes or custom), adjust active and DND windows.
3. Choose **发送到** — a dedicated conversation, or paste/bind an existing session id.
4. Press **保存**. The new rhythm applies immediately; **现在跟我说句话** sends one right away.

The first proactive message asks nothing in return — just reply in that conversation and it continues as a normal chat.

## Driving it from chat

The plugin registers a `chatmode` tool, so natural language works too:

| You say | It does |
| --- | --- |
| "打开主动聊天" / "turn on proactive chat" | enable and schedule |
| "每 30 分钟找我一次" | set `intervalMinutes: 30` |
| "午饭和晚上 11 点后别吵我" | edit DND windows |
| "就绑在这个会话里" | bind the current conversation as the target |
| "换个专用会话" | switch back to a dedicated conversation |
| "现在跟我说句话" | deliver one ping immediately |
| "主动聊天状态" | show runtime status |
| "关掉 / 恢复默认" | disable or reset everything |

## How it works

- A 30-second in-memory ticker decides whether a ping is due, respecting windows, daily caps and busy turns. It makes **no model request** unless a ping is actually delivered.
- Delivery goes through DSH's own schedule service: one far-future placeholder task holds the channel, and each ping calls `schedule.run(taskId)`. That keeps the Automation page clean and lets DSH wake or create the target conversation with the correct cwd and agent preset.
- The plugin adds a scoped system-prompt section (`## 主动聊天模式`) only to the target conversation, containing the topic pool and rules (short, no meta-talk, no tool calls, keep the conversation going).
- Delivered reminders render as a collapsed 「自动化任务」 row, not as a fake user bubble; the model's reply is the visible message.
- Settings live in `~/.dsh/chatmode/state.json`; edits do **not** restart the plugin.

## Settings reference

| Field | Default | Notes |
| --- | --- | --- |
| enabled | off | master switch |
| intervalMinutes | 60 | 5–1440 |
| jitterMinutes | 8 | random 0–N extra minutes |
| maxPingsPerDay | 12 | 1–200 |
| maxMessagesPerPing | 2 | 1–3 short lines per ping |
| activeWindows | 09:00–22:00 every day | empty = all day |
| dndWindows | 12:30–13:30, 23:00–08:00 | always wins over active |
| topics | 7 built-ins | one per line in the UI |
| customInstructions | empty | extra flavor for the topic pool |
| target | dedicated conversation | or `session` + session id |

Windows are JSON like `{"days":[1,2,3,4,5],"start":"09:00","end":"18:00"}`; `days` uses ISO weekdays 1=Monday…7=Sunday and may be omitted (= every day). Overnight windows such as `23:00–08:00` are supported.

## Privacy

- The plugin makes **no network requests** of its own.
- It reads and writes only `<DSH_HOME>/chatmode/state.json` and a rotating local log `<DSH_HOME>/chatmode/chatmode.log`.
- The settings API (`/api/chatmode/*`) is same-origin only and every request is admitted by DSH's own `connection.requestRejection()` host/browser authentication; if that service is unavailable the routes refuse to serve.
- No personal data is collected, uploaded or shared by this plugin.

## Limits

- DSH itself must be running (pings need the desktop client).
- Minimum interval 5 minutes; the schedule service also enforces a 60-second per-task delivery floor.
- The placeholder task in **Automation** is managed by the plugin — don't edit or delete it manually; turn the feature off instead.
- A ping is deferred when the target conversation is mid-turn; it never interrupts.
- The chat guidance prompt is Chinese by default; the settings UI is bilingual (中文 / English).

## Development

No build step: plain ESM for the host half, a hand-written `__ModuleLoader__` bundle for the browser half.

```bash
node --check index.js client.js lib/*.js
node tools/smoke-client.mjs   # renders the settings page in a tiny React stub
```

Files: `index.js` (host), `client.js` (Settings page), `lib/settings.js` (windows + planning), `lib/prompt.js` (prompt sections), `lib/web.js` (local API), `locale/*.json` (plugin metadata).
